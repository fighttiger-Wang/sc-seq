# 🟡 L2 功能模块轨 · 三问对齐与组件复用卡片

> **适用范围**：在现有 App 中新增一个独立页面、新增复杂业务弹窗、或对某个大型模块进行布局重构。  
> **核心铁律**：**拒绝 72 项大表轰炸！动手前先跑二开扫描，仅用大白话向用户确认 3 个核心问题，点头即做。**

## 1. 动手前必做：二开扫描与组件盘点

1. 运行 `node "<SKILL_DIR>/scripts/vibe-guard.js" anchor <项目目录>` 读取 `PROJECT_ANCHOR.md`。
2. 运行 `node "<SKILL_DIR>/scripts/vibe-guard.js" scan <项目目录>`，查清：
   - 项目现有的公共组件（优先直接复用）；
   - 项目 `DESIGN.md` 或 CSS 中已沉淀的配色、圆角、阴影 Token；
   - 是否存在同义函数（避免重复造轮子）。

## 2. 极简三问对齐（一次问完，不拆碎步）

用创作者听得懂的大白话，一次性向用户确认以下 **3 个核心问题**（提供推荐默认项，用户回“按推荐”即可直接开工）：

1. **📐 布局与主角（Layout & Hero）**：这个新模块采用哪种布局结构（如：Bento 多尺度网格 / 左右分栏工作台 / 居中模态卡片）？页面的视觉主角和唯一主按钮（Primary CTA）是什么？
2. **🎨 视觉质感与复用（Style & Reuse）**：默认100%继承当前项目 `DESIGN.md` 的配色与圆角体系，并复用现有组件 `[列出 scan 扫到的组件]`；是否需要从 `kit/` 引入特定的高保真动效零件？
3. **🔒 边界与持久化（Scope & Data）**：新模块的数据保存在哪里（如 `LocalStorage` 统一权威源），哪些现有文件/老功能是本次**绝对不碰**的？

## 3. 安全施工与交付闭环

1. **快照保护**：修改任何既有文件前必跑 `vibe-guard.js snapshot <files...>`。
2. **分层瘦身控制**：新增或修改的单个文件尽量控制在 **300 行以内**（若超过 300 行，建议将视图组件与状态逻辑拆分为独立模块）。
3. **完整性校验**：完工必跑 `vibe-guard.js verify`（确认老函数 0 丢失、无硬编码警告）及 `screenshot.js` 冒烟测试。
4. **自动沉淀与回执**：运行 `distill.js --positive` 记录新增的设计 Token，输出**创作者四格人话回执单**。
