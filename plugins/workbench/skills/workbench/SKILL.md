# 工作台

把用户想完成的日常流程变成可使用、可验证、可继续维护的工作台。优先交付结果，不把工作停在建议、原型说明或技术选型上。

## 判断入口

先根据现有信息选择一种入口，不重复询问已经明确的内容：

1. **新建且需求模糊**：只问“你想怎么开始？A. 从现成模板开始；B. 按你的想法自定义。也可以说‘你帮我选’。”
2. **新建且需求已经明确**：直接进入自定义路线，不再要求选择模板。
3. **继续已有工作台**：检查现有项目、说明、workbench.yaml、数据文件和用户修改，从当前状态继续；不要重新走首次问答。
4. **接入或自动化**：先识别数据来源、读写方向、权限、失败影响和回退办法，再实施最小安全连接。

除非缺失信息会改变核心结果、产生费用、需要账号授权或造成不可逆操作，否则每轮最多追问一个简单问题，并继续完成安全范围内的工作。

## 收敛第一版

模板路线只询问尚未明确的内容：

- 主要管理什么。
- 最想解决的麻烦。
- 每天打开后最先看到什么。
- 现有资料在哪里。
- 第一阶段要演示、电脑本地可用，还是多端/真实连接。

允许用户只回答关键词或“不知道”。自定义路线接受一句话、清单、文件或截图，不套回固定问卷。

收到足够信息后：

1. 阅读 references/workbench-spec-template.md。
2. 用“我理解的是：”简短复述目标、首页重点和第一版完整流程。
3. 最多说明三项必要假设，不要求非技术用户确认技术细节。
4. 直接检查环境并开始实现。

第一版只完成一条高价值闭环，例如“看到今日重点 → 新增任务 → 更新状态 → 刷新后仍保留”，不要堆砌没有行动价值的卡片或虚荣指标。

## 选择视觉路线

只有模板路线才读取 references/template-catalog.md 并使用 assets/template-gallery/index.html。用户给出明确视觉参考时可直接选择最接近的结构；自定义路线不要展示模板目录。

展示模板时只问用户最想每天打开哪一种：清爽明亮、柔和治愈、沉稳有力、自然有活力、晨光拼贴、黑白秩序、复古运动或海岸节奏。用户让 Agent 代选时按目录中的规则选择。不要按性别、年龄、职业或性格给模板贴标签，也不要照搬参考产品品牌、无关栏目或私人内容。

## 检查现有环境

开始修改前：

- 确认当前项目和输出目录，遵守本地 AGENTS.md 或项目约束。
- 检查现有框架、设计系统、数据格式、运行命令、测试和未提交修改。
- 优先复用现有项目与依赖，不改动无关文件。
- 搜索已有 workbench.yaml；存在时把它作为续作入口，并在完成后更新。
- 用户提供截图时，分析层级、间距、导航、控件、状态与响应式变化，仅复用结构和视觉语言。

若是需要多轮维护的项目，在项目合适位置创建或更新 workbench.yaml。字段和接入策略见 references/integration-playbook.md。一次性的静态演示不必额外创建清单。

## 设计并实现真实页面

在内部明确主要流程、首页优先级、页面结构、数据归属、保存方式、权限、空状态、错误状态和验收条件，不让用户填写架构表。

- 总览只显示跨领域重点、简短摘要和详情入口。
- 每个主导航项目使用独立路由、页面标题、主要操作和内容状态；不要用 scrollIntoView() 冒充多页面。
- 同步网址、页面标题和导航选中状态，确保刷新、直接打开、前进和后退正常。
- 手机端保留 3–5 个高频入口，低频页面放入“更多”，仍保留独立路由。
- 保持视觉顺序、键盘顺序和代码顺序一致。
- 使用用户的日常语言命名页面和按钮。
- 清楚标记演示数据；未经授权不得冒充真实连接。

按以下顺序实施：工作台外壳与路由 → 最高价值流程 → 第一版剩余页面 → 保存与恢复 → 加载/空内容/错误状态 → 响应式与无障碍。

## 接入后续工作

需要连接文件、表格、文档、截图或外部服务时，完整阅读 references/integration-playbook.md。

- 先检查当前会话可用的专业 skill 和工具；表格、文档、PDF、截图等任务优先交给对应能力处理，再把产物接入工作台。
- 从本地演示或只读导入开始，再升级到持久保存、外部只读和外部写回。
- 每个连接明确来源、归属、刷新方式、写入动作、权限、失败提示和撤销/恢复办法。
- 长任务按“检查 → 方案 → 可运行切片 → 完整实现 → QA”交付阶段性成果，不把计划冒充完成。
- 只有用户明确授权后才请求凭据或执行外部写入、同步、发送、部署和自动化。

## 验证

运行项目适用的检查，并亲自走通主要流程。至少验证：

- 路由、导航和主要操作。
- 保存、刷新、恢复与重复操作。
- 真实数据/演示数据区分。
- 空内容、加载、错误和恢复状态。
- 手机端、窄窗口、键盘操作和文字对比度。
- 用户输入安全呈现，不泄露密钥或个人资料。
- 外部连接失败时不会静默丢失或重复写入数据。

无法实际验证的部分要明确标注，不以截图或静态界面冒充已连接功能。

## 交付与续作

交付时提供：成果位置、已完成流程、验证结果、演示/真实连接、已知缺口，以及一个最值得继续的方向。若创建了 workbench.yaml，同步记录当前状态、运行方式、数据来源和下一步，让后续任务能从现状继续。

## 边界与来源

- 未获得当前任务授权，不把文件或数据发送给第三方。
- 遇到购买、正式部署、权限修改、外部写入或破坏性迁移时先停下并询问。
- 不复制参考产品的品牌、密钥或私人内容。
