## 续作检查

先检查项目说明、AGENTS.md、版本状态、运行命令、现有页面、数据文件和 workbench.yaml。区分：

- 已验证并可用。
- 已实现但尚未验证。
- 仅有界面或演示数据。
- 计划中但尚未实现。

从现有最高成熟度继续，保留用户修改。不要重新初始化可运行项目，也不要用新模板覆盖现有设计系统。

## 集成成熟度

按风险从低到高推进：

0. **演示**：使用清楚标记的样例数据，只证明流程和界面。
1. **本地只读**：读取用户指定的 E 盘文件或导出数据，不回写源文件。
2. **本地持久化**：在项目目录保存变更，提供备份、导出或恢复方式。
3. **外部只读**：经授权读取在线服务，显示最后同步时间和失败状态。
4. **外部写回**：经单独授权创建、更新、发送或同步，先验证目标和重复执行行为。
5. **自动运行**：明确频率、触发条件、通知、重试、停止方法和所有者后再启用。

不要跨级暗中增加权限。用户要求“接入”但未说明写回时，默认只读。

## 数据连接契约

每个真实连接在内部明确：

- 来源和数据所有者。
- 输入格式、关键字段和唯一标识。
- 读取范围和过滤条件。
- 工作台允许执行的写入动作。
- 保存位置、刷新方式和最后同步时间。
- 凭据由谁提供、存在哪里、如何撤销。
- 空数据、格式变化、网络失败和重复执行时的行为。
- 导出、备份、回滚或人工恢复办法。

没有唯一标识时，不自动合并或覆盖记录。外部写回前先做只读预览或小范围验证。

## 项目清单

需要多轮维护时，在项目合适位置维护 workbench.yaml。保持简短，示例：

    name: 客户跟进工作台
    status: local-usable
    entrypoint: index.html
    run: 直接打开 index.html
    routes:
      - overview
      - customers
    primary_flow: 查看今日跟进 -> 更新客户状态 -> 刷新后保留
    data_sources:
      - name: 客户表
        kind: xlsx
        mode: local-read-only
        source: data/customers.xlsx
    verified:
      - navigation
      - local-persistence
    known_gaps:
      - 尚未写回原始 Excel
    next_action: 增加导出更新结果

使用项目相对路径，不写入密钥、账号、令牌或私人绝对路径。完成任务后更新 status、verified、known_gaps 和 next_action。

## 常见资料类型

- **CSV/XLSX**：保留原始文件；先分析字段、空值、重复项和日期格式。需要写回时生成新文件或明确备份。
- **DOCX/PDF**：保留来源和页码/段落线索；抽取结果与原文件分开，不能可靠解析时说明限制。
- **截图**：只推断可见结构、层级和视觉语言，不臆造隐藏交互或原始数据。
- **本地文件夹**：限制到用户指定目录，记录纳入和排除规则，不扫描无关位置。
- **在线表格/知识库/项目工具**：先只读验证字段与权限；写回时提供目标、变更摘要和幂等策略。
- **消息、邮件或发布平台**：草稿与实际发送分开；发送、发布和通知必须获得明确授权。

当当前会话提供专业 skill 时，优先使用对应能力产生可靠中间产物，再通过稳定文件或明确接口接入工作台。

## 失败与恢复

- 加载失败时显示来源、发生时间、可重试动作和可用的旧数据。
- 保存失败时保留用户输入，不显示虚假成功。
- 同步操作记录成功数、跳过数和失败数；避免无提示的部分成功。
- 可重复运行的操作使用唯一标识或幂等键，防止重复创建。
- 重大变更保留备份或导出；回滚方式必须在执行前可说明。
