# 工作台内部方案模板

完成用户需求了解后阅读本文件，只使用与当前请求相关的部分。

本方案只供 Agent 内部使用。向用户只提供简短、自然的复述。除非用户主动询问或明显熟悉技术，否则不要展示架构、数据结构、持久化、API、模拟数据或验收条件等术语。

## 默认假设

只有用户把选择交给 Agent 时，才使用以下默认值：

- 在当前项目中搭建本地优先、可适配不同屏幕的网页应用。
- 优先服务一个主要用户和一条反复出现的日常流程。
- 使用 4–6 个板块、紧凑左侧导航和聚焦的主区域；除非右侧区域能直接帮助当前任务，否则不增加右侧栏。
- 第一条完整流程使用本地演示数据，并清楚标注。
- 优先复用现有技术环境和设计系统。没有现成应用时，选择当前环境已经具备、最容易维护的方案。
- 第一版不加入账号登录、付费、正式部署和外部写入。
- 用户没有视觉偏好时，使用平静、不拥挤的布局，每个页面保留一个明确主操作。

### 验收条件

写 3–8 条可以直接观察的结果，优先使用以下形式：

> 在某个开始状态下，当用户完成某个操作后，页面应该出现什么结果。

至少包含一条主要流程条件，以及一条空内容或失败状态条件。

## 常用板块参考

只有板块能帮助用户做决定或采取行动时，才加入：

- 今日总览：重点、日程和下一步行动。
- 任务流程：记录、状态、负责人和截止时间。
- 内容工作室：选题、草稿、素材、检查和发布状态。
- 学习中心：目标、资料、练习和进展证据。
- 客户或项目中心：健康状态、里程碑、风险和下一步行动。
- 运营面板：队列、提醒、审批和操作说明。
- 知识桌面：搜索、来源、笔记和可复用成果。

避免只展示数据、却不能帮助用户判断或行动的板块。

## 检查清单

- 首页能让用户马上看出下一步做什么。
- 第一版每个板块都有明确作用和主要操作。
- 导航名称使用用户自己的语言。
- 真实数据和演示数据能够区分。
- 保存和刷新行为已经明确。
- 空内容、加载和错误状态能够使用。
- 窄窗口下仍然清楚且可操作。
- 键盘焦点和文字对比度足够。
- 源码和截图中没有嵌入密钥或个人资料。
- 每条验收条件都已经实际检查，或明确标记为尚未验证。
