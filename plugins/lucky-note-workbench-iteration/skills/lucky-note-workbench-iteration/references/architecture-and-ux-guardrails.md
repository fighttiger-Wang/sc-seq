# Lucky_Note (LumaTrack) 架构契约与苹果极简设计指南

## 一、 跨进程生命周期与双向握手契约

### 1. 启动生命周期时序原则
```
[C# 宿主] MainPage_Loaded 异步读盘 (app-state.json)
    │
    ├── 1. 读取、迁移与重新调度计算
    ├── 2. SaveAsync 落盘
    ├── 3. 渲染 XAML 原生视图
    └── 4. 强制推送：await PushStateToWebViewAsync()  <-- 必须显式调用！
          ▲
          │ 握手通信通道
          ▼
[WebView2 网页] workbench.html 加载
    │
    ├── 1. DOMContentLoaded 发送 postToHost('page_ready', {})
    └── 2. 防御性心跳重试：若 realAppState 未挂载，每 300ms 持续重试（最多 50 次熔断）
```

- **C# 守则**：`MainPage.xaml.cs` 无论因磁盘 I/O 耗时多久，业务数据就绪后必定在 `MainPage_Loaded` 末尾主动执行 `await PushStateToWebViewAsync()`。
- **JS 守则**：前端网页不能单次发送 `page_ready` 后就静止，必须具备定时心跳检测保底，确保数据必达。
- **缓存规避**：每次涉及前端 `workbench.html` 或 `workbench_engine.js` 的修改，必须同步在 `MainPage.Workbench.cs` 中递增导航 URL 版本号（`?v=X.Y.Z`），同时在 HTML 内更新 `<script src="workbench_engine.js?v=X.Y.Z">`。

## 二、 苹果 macOS HIG 视觉与交互规范

### 1. 2×2 四宫格对称布局
- **四大核心凭证区域**：
  - 左上：集群物理路径（`+ 添加路径`）
  - 右上：云路径（`+ 添加云路径`）
  - 左下：公司编号（`+ 添加编号`）
  - 右下：云编号（`+ 添加云编号`）
- **按钮放置规则**：各区域的操作按钮必须位于该模块标题栏的右上角，绝不在输入框内部或底栏堆砌占位小胶囊，保持“短凭证区”视觉秩序。

### 2. 微胶囊内嵌标签体系
- **单条状态**：默认呈现轻量徽标（如 `#1`），点击后无缝转入输入框（最多 5 字符）。
- **多条状态**：自动展开并列胶囊，支持独立输入阶段/版本标签（如 `正常`、`强制后`、`换基因组`、`V2`）。
- **联动反馈**：
  - 复制单项时，Toast 提示自动带上标签识别（例如：`已复制 云编号 (强制后)`）。
  - 「项目信息」一键综合复制与「交付通知预览」自动关联标签输出。

### 3. 字阶与色彩系统
- 遵循苹果原生中性浅灰底色（`#ECECEE`）、卡片纯白底（`#FFFFFF`）与深色适配。
- 文本层级：
  - 标题：`text-xl` / `text-2xl font-black`
  - 正文：`text-sm font-medium`
  - 辅助说明与标签：`text-xs` / 10~12px `font-semibold`
  - 等宽字体：项目编号、云编号、路径统一使用 `font-mono`。

## 三、 主动架构演进路线图（顾问提案指南）

当工作区项目规模进一步增长或用户提出性能要求时，AI 应主动以“体验语言”向用户提请以下演进：

1. **轻量嵌入式数据库（SQLite / LiteDB）替代单大 JSON**：
   - *体验收益*：读写由“每次全量重写 840KB 纯文本”升级为毫秒级按需存取，彻底消除几百个项目时的保存卡顿与崩溃隐患。
2. **巨石前端解耦为模块化组件**：
   - *体验收益*：将 7,200 行的 `workbench_engine.js` 拆分成 `memo.js`、`cards.js`、`workflow.js`、`snippets.js`。单一模块代码有异常绝不影响全局，提高软件韧性。
3. **本地离线瞬间开屏缓存（IndexedDB）**：
   - *体验收益*：实现真正的 0 秒即时呈现，打开软件完全看不到任何数据加载缝隙。
