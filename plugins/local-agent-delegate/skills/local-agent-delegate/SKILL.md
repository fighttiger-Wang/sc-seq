## 底层动态探测与防崩熔断机制（Zero-Crash Guard）

针对不同 CLI 的专有代号机制，系统实施**实机探测与安全拦截**：

1. **自动探测源**：
   * **Codex**：启动时自动扫描并解析 `~/.codex/models_cache.json`，动态提取真实授权的 slug 代号。
   * **DeepSeek**：自动读取 `~/.codex/cc-switch-model-catalog.json` 与安装包中的模型配置。
2. **防崩熔断兜底**：
   * 每次向 Codex 派发任务时，脚本会自动校验参数是否在本地 `models_cache.json` 白名单中。
   * 若模型参数不在白名单内，脚本会**主动忽略 `-m` 参数**，回退至当前客户端的默认认证模型，从物理层确保绝不发生 CLI 参数报错。

## 快捷交互指令集

| 指令 | 作用说明 |
| :--- | :--- |
| **`?`** | 实时探测并呼出上方的真机选项矩阵与当前运行状态。 |
| **`1A` ~ `2J`** | 切换审查官为指定实机模型（例如 `2I` 立即切换为 Codex 5.6 Terra，`1A` 切换为 DeepSeek-V4-Pro）。 |
| **`1` ~ `5`** | 切换指定 Agent 并智能使用其实机默认模型（例如输入 `1` 默认 `1A`，输入 `2` 智能对齐 GUI 勾选项 `2I`）。 |
| **`0`** 或 **`暂停`** | 立即冻结当前对抗轮次，停止推进且不消耗额外 Token。 |
| **`继续`** 或 **`resume`** | 解除暂停，继续由当前选定模型进行红队挑刺。 |

## 自治双脑对抗闭环运行（无人值守闭环）

如果希望作者模型（Codex）与审查官模型（DeepSeek）在后台**完全自主完成多轮对攻挑刺、修复反例、直至通过才交付**，直接运行闭环控制器：

```powershell
& 'C:\Users\fight\.codex\cache\ngs-analysis-workbench\venvs\0.2.10\Scripts\python.exe' `
  'C:\Users\fight\.gemini\config\skills\E06-本机智能体委托\scripts\adversarial_loop.py' `
  --task "编写工业级健壮模块" `
  --file ".swarm/draft.py" `
  --output "src/final_output.py" `
  --max-rounds 3
```

* **自动多轮推进**：Author 针对上一轮 Critic 提出的边界漏洞与具体反例逐一靶向修复；
* **两阶段提交**：草稿阶段绝不污染正式文件，只有获得 `[STATUS: APPROVED]` 时才会两阶段提交覆盖到 `--output`；
* **实时热干预**：循环每轮执行前均核验状态，用户在终端或对话中输入 `0` / `暂停`、`1A`、`2I`，循环会立即感知并挂起或切换审查官。
